折叠生成文件：linguist-generated vs gitlab-generated

生成文件（dist/、*.min.js、lock 文件）有两个麻烦：把仓库语言占比统计带歪，把 PR diff 撑出几千行。两个平台都在 .gitattributes 里解决，但机制差别比想象大——GitHub 一个 attribute 全包，GitLab 按用途拆成三套，标错只生效一半。

GitHub：linguist-* 一个搞定两件事

GitHub 的语言统计和 diff 折叠都归 Linguist 一套管，所以 linguist-generated 一标同时踢出语言统计 + 折叠 diff：

dist/* linguist-generated
package-lock.json -linguist-generated   # 前导 - = 反向排除

同家族还有 linguist-vendored（第三方库）、linguist-documentation（文档）、linguist-language=PHP（改判语言）。判准：generated = 机器产物，vendored = 别人的代码，都被踢出统计，区别只在 diff 折不折叠。

attribute 不计统计 diff 折叠
linguist-generated ✅ ✅
linguist-vendored ✅ ❌
linguist-documentation ✅ ❌

GitLab：三套各管一摊

GitLab 只有两个 gitlab- 专属 attribute，各自只干一件事；语言统计反而借用 GitHub 的 linguist-*——它的统计引擎 go-enry 是 Linguist 的 Go 移植，认 linguist- 前缀。

用途 GitLab 用什么
MR diff 折叠 gitlab-generated（专属）
语法高亮改判 gitlab-language=prolog（专属，=text 关高亮）
语言统计排除/改判 linguist-generated / linguist-vendored / …

最大的坑：在 GitLab 标 gitlab-generated 只折叠了 diff，文件照样算进语言占比；想同时从统计里拿掉，得再补一条 linguist-generated。和 GitHub 一个 attribute 全包正相反。

*.min.js gitlab-generated      # 只折叠 diff
*.min.js linguist-generated    # 才会从语言统计条消失

另注：GitLab 会自动识别部分生成文件（protobuf 产物、go generate 的 Go 文件、source map），不标也可能折叠，这也是“有的折有的没折”不一致反馈的来源（#572763）。

共同点：都是 .gitattributes 的 override

linguist-* / gitlab-* 和 LFS 的 filter=lfs、文件锁 lockable、行尾 text=auto 堆在同一个文件。记法：git 原生 attribute（filter / text / merge）各平台通用；带平台前缀的只在对应平台网页生效，换到本地仓库一律失效。

See Linguist overrides / GitLab Git attributes。

GitHub URL 隐藏参数：`.diff` / `?w=1` / `compare@{时间}` 工作流

GitHub 网页 URL 上有一组 2012 年就存在、UI 从没暴露过的参数。LLM 工作流让它们价值翻倍 —— curl 一个 .diff URL 直接拿到纯文本 diff 喂给 prompt，比让 LLM 自己抓网页快也准。下面所有链接都点得开（用 laravel/framework 演示）。

.diff / .patch —— 任何 PR / commit / compare 页 URL 加扩展名，返回纯文本：

curl -L https://github.com/laravel/framework/pull/10000.diff
curl -L https://github.com/laravel/framework/pull/10000.patch

.diff 体积最小，适合喂 LLM；.patch 多带 commit metadata（作者、邮箱、时间），适合 git am / cherry-pick。commit / compare URL 同样支持。

?w=1 —— 任何 diff URL 加上，忽略纯 whitespace 改动：

https://github.com/laravel/framework/pull/10000/files?w=1

把 indent 调整 / 换行符变化彻底从视野抹掉，只剩真改动。refactor / formatter 大重写后救命。

?ts=4 —— diff / blob 页改 tab 渲染宽度：

https://github.com/laravel/framework/blob/master/src/Illuminate/Foundation/Application.php?ts=4

数值任意（?ts=2 / ?ts=8），只改你眼里的呈现，远端文件不变。在 tab 缩进的项目（Go / Linux kernel）里效果最直观。

#L16-L25 —— 行号锚点 + range：

https://github.com/laravel/framework/blob/master/src/Illuminate/Foundation/Application.php#L1-L20

提 PR 评论、写文档、给同事丢 issue 时定位用，比“Application.php 大概第 20 行”准多了。

compare/<base>@{<时间>}...<head> —— compare 页接受时间锚点，不只是 SHA / branch：

https://github.com/laravel/framework/compare/master@{1.week.ago}...master

https://github.com/laravel/framework/compare/master@{2026-05-01}...master

语法和 git log @{...} 一致。release notes 起草、“上周改了啥”周报、incident 后回溯都用得上。

GitHub README 图片报 Content length exceeded

GitHub 把 README / issue / wiki 里所有外链图都走 Camo 匿名代理（隐藏访问者 IP 和 referer），代理默认 5 MB 上限。超过的图加载失败，alt 文字被替换成 Content length exceeded。

5 MB 写死在 CAMO_LENGTH_LIMIT：

content_length_limit = parseInt(process.env.CAMO_LENGTH_LIMIT || 5242880, 10)

5242880 / 1024 / 1024 = 5。压缩或裁剪到 5 MB 以下是唯一办法——GitHub 强制代理，自托管也绕不开。
